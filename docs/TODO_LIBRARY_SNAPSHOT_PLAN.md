# Library Snapshot Reload Plan

Status: Phase 1 implemented. Needs simplification pass, build, and tests.

## Problem

Pressing **Reload Library** can replace `KitLib::LibraryManager` while current `InstrumentSynth` objects still store raw pointers into the old library data.

Example:

- `InstrumentSynth::lastRoutingContext.defaultInstrument`
- `InstrumentSynth::lastRoutingContext.artSources`
- `InstrumentSynth::instrumentSpecstPtr`
- `SampledSound::instrumentSpec`
- `SampledSound::sampleVariantSpec`

After reload, these pointers can point to freed memory. Then a route rebuild can crash when it reads `InstrumentSpec` or `ArticulationSpec`.

Known crash path:

- `../source/PluginEditor.cpp`: `PluginEditor::reloadLibraryFromTroubleshooting`
- `../source/Engine/DrumKitEngineController.cpp`: `DrumKitEngine::reloadAll`
- `../source/Engine/DrumKitEngine.cpp`: `DrumKitEngine::useInstrumentMap`
- `../source/Engine/InstrumentSynthLoader.cpp`: `InstrumentSynth::resolveArticulationSpec`

## Goal

Reload the library without invalidating synths that are still in use.

Reuse unchanged synths when the map and resolved source instrument folders did not change.

## Non-goals

- Do not rewrite the full kit model to use `shared_ptr` for every object.
- Do not hash audio contents.
- Do not support wildcard `*` instrument maps.
- Do not implement articulation-level partial reload in the first version.
- Do not change realtime audio behavior.

## Assumptions

- `LibraryManager` owns all `DrumKitSpec`, `InstrumentSpec`, `ArticulationSpec`, `VelocityLayerSpec`, and `SampleVariantSpec` objects.
- Keeping the owning `LibraryManager` alive keeps current raw model pointers valid.
- Reload decision is slot-level: if any source instrument used by a slot changed, reload that slot.
- Instrument-level folder fingerprint is enough for now.
- Sample audio content can change without size or timestamp changing, but that is rare. Later sample filenames may include a short checksum suffix generated by `../scripts/analyze_drum_samples.py`.

## Target Design

### Library snapshots

`DrumKitEngine::libraryManagerPtr` should be:

```cpp
std::shared_ptr<KitLib::LibraryManager>
```

`DrumKitEngine::initSampleLibrary()` creates a new `shared_ptr<LibraryManager>` and scans it before publishing it as the current snapshot.

Old snapshots stay alive while old synths hold them.

### Synth snapshot ownership

`InstrumentSynth` keeps:

```cpp
std::shared_ptr<const KitLib::LibraryManager> librarySnapshotPtr;
```

Engine load paths pass the current snapshot when loading synths. The synth can still use raw pointers internally, because the snapshot owns the objects behind those pointers.

When `InstrumentSynth::unloadInstrument()` runs, it clears `librarySnapshotPtr`.

### Layout-only replacement

`../source/Engine/DrumKitEngineMapHelpers.cpp` has `createReplacementSynth()`.

When it copies a loaded synth because only layout data changed, it must copy the source synth snapshot too. This keeps old raw pointers valid in the replacement.

### Simple instrument fingerprint

Use only:

```cpp
juce::String InstrumentSpec::getContentFingerprint() const;
```

Remove these detailed fingerprints unless a later phase needs them:

```cpp
SampleVariantSpec::getContentFingerprint()
VelocityLayerSpec::getContentFingerprint()
ArticulationSpec::getContentFingerprint()
DrumKitSpec::getContentFingerprint()
LibraryManager::getContentFingerprint()
```

`InstrumentSpec::getContentFingerprint()` should scan `meta.rootDir` and build a short stable hash from:

- instrument folder path or code
- sorted relative child directory names
- sorted relative audio file paths
- each audio file size
- each audio file modification time

This is enough for slot-level reload:

- file renamed -> fingerprint changes
- file added -> fingerprint changes
- file deleted -> fingerprint changes
- file size changed -> fingerprint changes
- file modified time changed -> fingerprint changes
- articulation folder renamed -> fingerprint changes

### Slot fingerprint

Slot fingerprint should include:

- map entry fingerprint
- each resolved source instrument folder fingerprint

Then compare:

```cpp
oldSlotFingerprint != newSlotFingerprint
```

If different, reload the whole slot.

### Sample loader cache

Keep `SampleLoader` alive across library reloads. Otherwise an unchanged reused synth could lose pending sample loads from the old queue.

The sample cache key includes file path, file size, and modification time. This lets unchanged files reuse cache, while changed files get a new cache key.


Future sample file names may include a short checksum suffix like `-#WhAtEvErHaSh`, generated by a script such as `../scripts/analyze_drum_samples.py`. Because the path is already part of the key and fingerprint, this suffix will naturally affect reuse decisions.

### Remove wildcard mapping

Remove `*` instrument map support everywhere.

No backwards compatibility and no special user notification is needed.

Remove from `../source/Engine/DrumKitEngine.cpp`:

- `slotId == "*"` branch
- wildcard kit resolving
- `wildcardKitSpec`
- `wildcardChanged`
- `forceApplyAllSlots`
- wildcard-triggered `mapKit(*wildcardKitSpec)` inside `useInstrumentMap()`

If parsing still accepts `*`, let normal explicit-slot validation fail or remove parser support too during the wildcard cleanup phase.

## Articulation-Level Reload Decision

Do not implement articulation-level reload now.

Reason:

- Current runtime replacement is whole `InstrumentSynth` based.
- Articulation-level reload would need partial sound unload, partial routing rebuild, alias handling, shadow synth handling, and CC table safety.
- The risk is higher than the likely benefit right now.

Later option:

- Add articulation folder fingerprint only if whole-slot reload is measured as too slow.
- Only do that after tests around aliases, layered articulations, and hihat controller routing exist.

## Phases

### Phase 1 - Keep Snapshot Safety

Status: implemented, not built or tested.

Work:

- Keep `DrumKitEngine::libraryManagerPtr` as `std::shared_ptr<KitLib::LibraryManager>`.
- Keep `InstrumentSynth::librarySnapshotPtr`.
- Pass snapshots from engine load paths.
- Copy snapshot in layout-only replacement synths.

Verification:

- Build `Tests`.
- Confirm synths loaded before Reload Library can still rebuild routing without accessing freed library memory.

### Phase 2 - Simplify Fingerprints

Status: planned next.

Work:

- Remove detailed fingerprint methods from sample, velocity, articulation, kit, and library classes.
- Keep only `InstrumentSpec::getContentFingerprint()`.
- Implement it from `meta.rootDir` directory/file metadata.
- Return a short stable hash, not the full collected text.
- Update slot fingerprint code to append only resolved source instrument hashes.

Verification:

- Same instrument folder gives same fingerprint.
- Added, removed, renamed, resized, or modified-time-changed audio file changes fingerprint.
- Renamed articulation folder changes fingerprint.

### Phase 3 - Remove Wildcard Mapping

Status: planned next.

Work:

- Remove wildcard branch and variables from `DrumKitEngine::useInstrumentMap()`.
- Remove wildcard full-kit reload path.
- Remove parser wildcard support if it exists and is easy to isolate.
- Keep only explicit slot mappings.

Verification:

- Explicit maps still apply.
- No `slotId == "*"`, `wildcard`, or `forceApplyAllSlots` code remains in engine map apply path.

### Phase 4 - Verify Reload Behavior

Status: not done.

Work:

- Build `Tests`.
- Run focused tests for instrument fingerprint and map reload decisions.
- Manually test in REAPER:
  - load a kit
  - wait briefly
  - press **Reload Library**
  - confirm no crash
  - confirm unchanged slots are reused
  - confirm changed source instrument folder reloads that slot

### Phase 5 - Optional Articulation-Level Reload

Status: later only if needed.

Do this only if whole-slot reload is measured as too slow.

Work would include:

- articulation folder fingerprint
- partial sound reload rules
- partial routing rebuild rules
- hihat/CC safety tests
- layered-shadow synth tests

## Open Questions

- Whole-library generation number: decide later if logs need it.
- Full sample content hash: later todo. Prefer a short checksum suffix in sample file names if it becomes useful.
- Preview sample jobs: copied file paths are probably enough; do not add snapshot ownership unless preview starts storing raw library pointers.
